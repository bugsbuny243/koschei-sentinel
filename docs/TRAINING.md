# Koschei Sentinel Training

Koschei Sentinel v0.6 added the first executable adapter-training lane. Version 0.7 adds a separate real-dataset readiness boundary so a structurally valid but tiny, concentrated, or incomplete release cannot silently become the basis of a real training run.

## What this phase trains

The trainer performs supervised QLoRA/LoRA fine-tuning against a pinned base-model revision. Each training row contains:

1. the fixed Sentinel system contract;
2. one pseudonymized `sentinel.case.v1` evidence packet;
3. one policy-valid `sentinel.opinion.v1` target.

The initial target is generated by the deterministic Sentinel baseline. This teaches the adapter the exact output shape, evidence citation discipline, authority boundary, confidence ceiling, and abstention behavior. It does not yet add new expert knowledge. Later dataset releases can replace baseline targets with reviewed expert commentary while keeping the same validation gates.

## Safety properties

- The base model must use an `owner/model` registry identifier.
- `base_revision` must be a full 40-character immutable commit SHA.
- `trust_remote_code` is permanently false in the v1 contract.
- Dataset, readiness-report, and output paths must remain inside the repository root.
- Every train, validation, and test digest is checked against the quality manifest before model loading.
- Real-training configs require a passing readiness report stored inside the exact dataset release.
- The readiness report is bound to the SHA-256 digest of that release's quality manifest.
- Dataset rows are parsed again as `sentinel.dataset.v1`.
- Supervised answers are validated against the Sentinel evidence policy.
- Existing output directories are never overwritten.
- Adapter artifacts receive a deterministic content digest and `sentinel.adapter-manifest.v1` manifest.
- Normal CI performs no model download, network call, GPU operation, or paid inference.

## Prepare a real dataset release

Use the one-shot private builder with raw ARVIS exports that remain outside Git:

```bash
export SENTINEL_DATASET_SALT='replace-with-a-secret-manager-value'

sentinel-dataset-build \
  --input /private/arvis-export-001.json \
  --input /private/arvis-export-002.jsonl \
  --output-dir build/releases/sentinel-v0.7-training \
  --salt-version production-2026-08 \
  --policy configs/readiness/training-ready.v1.json
```

The resulting ready directory contains:

```text
build-manifest.json
quality-manifest.json
readiness-report.json
train.jsonl
validation.jsonl
test.jsonl
```

The builder rejects malformed or duplicate records and materializes no final release unless the readiness policy passes. See [`DATASET_READINESS.md`](DATASET_READINESS.md).

## Validate the training plan

The pinned T4 configuration already uses the verified Qwen2.5 1.5B base revision, 4-bit NF4 quantization, and `float16` compute:

```bash
pip install -e '.[dev]'
sentinel-train \
  --config configs/training/qlora.t4.qwen2.5-1.5b.json \
  --plan-output build/training/qwen2.5-1.5b.plan.json
```

This phase is network-free and does not require the training dependencies. The planner revalidates the complete release and its readiness binding. Inspect the plan before allowing GPU execution.

## Execute on Google Colab or another CUDA host

Use a CUDA runtime, place the private repository and materialized dataset release in the runtime, then install the optional training stack:

```bash
pip install -e '.[dev,training]'
sentinel-train \
  --config configs/training/qlora.t4.qwen2.5-1.5b.json \
  --plan-output build/training/qwen2.5-1.5b.plan.json \
  --execute
```

The trainer loads the pinned base revision with 4-bit quantization, prepares it for k-bit training, injects LoRA adapters, masks system and user prompt tokens from the loss, trains only on assistant output tokens, and writes the adapter atomically.

Expected output shape:

```text
build/training/<run-id>/
  adapter/
  adapter-manifest.json
  checkpoints/
```

Do not commit model weights, raw ARVIS exports, private dataset releases, Hugging Face tokens, pseudonymization salts, or runtime secrets to this repository.

## Promotion remains separate

A passing readiness report permits training to start; it does not establish model quality. A completed adapter is not automatically trusted or deployed. The next phase must run local PEFT inference through the expanded Sentinel benchmark, compare it against the deterministic baseline and Together reference candidates, and refuse promotion when any hard authority, grounding, abstention, privacy, or confidence gate fails.
