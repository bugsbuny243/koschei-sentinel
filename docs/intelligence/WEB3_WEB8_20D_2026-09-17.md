# Web3–Web8 Intelligence — Koschei Sentinel

Window: 2026-08-29 → 2026-09-23

Sentinel is treated as a cybersecurity foundation model, not a scanner.

## Existing capability directions
Trust-chain reasoning; multi-hop authorization; action finality; PQ migration; cross-chain causality; artifact identity; standards lifecycle; accountability; intent-resolution continuity; control-plane/effect continuity; model-to-effect causality; runtime revocation.

## 2026-09-23 fresh intake

### MCP security posture now has a large current measurement
The September 23 MCP Security Index reports 29,132 scanned MCP servers: 16% graded D/F and 46% declaring no authentication. Popularity and security posture were not strongly aligned.

**Opportunity:** add ecosystem-scale security-posture reasoning without treating a static score as proof of safety.

**Threat:** agent ecosystems can accumulate large numbers of reachable tools whose identity/authentication and provenance are weak or unverifiable.

**Competitor gap:** combine posture observations with authority, artifact identity, runtime behavior and actual downstream effect rather than producing only configuration scores.

**Benchmark/product idea:** `MCP_TRUST_CONTINUITY`: reason across `discovery -> server identity -> auth metadata -> tool artifact/version -> delegated credential -> invocation -> effect -> evidence`, including missing/unverifiable metadata.

### AI gateway management plane can become pre-handshake execution authority
A critical Bifrost AI-gateway issue (CVE-2026-90898) was reported on 2026-09-23: affected HTTP transport configurations could allow an unauthenticated management request to register an stdio MCP client, with command execution occurring before the normal MCP handshake. Patched transport versions are reported from v2.1.0 onward.

**Opportunity:** strengthen Sentinel's reasoning around control-plane ordering and precondition violations.

**Threat:** security checks can exist yet occur after a dangerous side effect has already happened.

**Competitor gap:** detect `effect-before-authentication/verification` as a causal invariant failure, not merely match a known CVE.

**Benchmark idea:** `PRECONDITION_ORDERING`: identify execution paths where registration/materialization/startup effects precede authentication, handshake, policy or artifact verification.

### Proof-of-Control formalizes the open-verification direction
LF Decentralized Trust and Advanced AI Society launched Proof-of-Control work on 2026-09-23 around tamper-evident evidence generated while non-deterministic agents act and independently verifiable controls.

**Opportunity:** this strongly validates Sentinel's evidence + authority + effect direction.

**Threat:** “verifiable evidence” can still be over-trusted if it proves mechanism execution but not correct authority, fresh state or safe outcome.

**Competitor gap:** reason about what an evidence object actually proves and what it does not prove.

**Benchmark idea:** `EVIDENCE_SEMANTICS`: given signed/tamper-evident receipts, determine whether they establish identity, policy compliance, state validity, authorization, execution, effect or only a subset.

### Agent security vendors continue shifting from output safety to action risk
New September 23 security material emphasizes constraining an agent's next action and correlating intent with data/tool access. This is a competitive signal, not a new protocol standard.

**Implication:** Sentinel differentiation must remain deep causal cybersecurity reasoning across identity, authority, state, software supply chain, network reachability, protocol invariants and real effects.

## Standards reality
No accepted IETF/W3C Web4/Web5/Web6/Web7/Web8 generation standard was identified in the last 24 hours. Proof-of-Control is open-community/LFDT work; MCP is an open application protocol; today's security products and measurements are deployment/security developments, not new Internet-generation standards.
