# Web3–Web8 20-Day Intelligence — Koschei Sentinel

Window: 2026-08-29 → 2026-09-17

Sentinel is treated here as a cybersecurity foundation model, not a scanner.

## What matters to Sentinel

### 1. Trust-chain reasoning
Modern failures cross code, infrastructure and protocol boundaries. Alephium’s bridge postmortem is a strong training case: an off-chain validation weakness plus an eclipse-style network condition led legitimate guardians to produce cryptographically valid but unauthorized messages.

**Model capability:** reason across `identity -> credential -> code -> observation source -> protocol rule -> authorization -> state transition -> effect -> evidence`. Do not equate valid signatures with valid state.

### 2. Multi-hop agent authorization
Current IETF drafts separately explore attenuated agent delegation, human delegation provenance, AI agent identity/resolve/invoke/receipts and execution-finality. They are not RFCs, but they expose a stable security problem.

**Model capability:** distinguish `authentication != standing capability != delegated scope != per-action authority != execution != effect`. Train scope attenuation, expiry, delegation depth, provenance and replay/revocation reasoning.

### 3. Computation is not authority
The September execution-finality draft formalizes a useful defensive principle: model output/tool selection does not itself authorize a real-world consequence. A proposed action can remain non-effective until act-specific predicates are independently verified.

**Model capability:** analyze whether an action is authorized for this principal, scope, resource, time and consequence—not merely whether the model/tool/session is trusted.

### 4. Post-quantum cybersecurity reasoning
Ethereum’s September 7 priorities target L1 quantum resistance across execution, consensus and data by December 2029. The migration is heterogeneous: accounts can gain signature agility while consensus cryptography needs coordinated fork changes.

**Model capability:** cryptographic dependency graphs, migration sequencing, hybrid/classical/PQ compatibility, key lifecycle, proof-system assumptions and operational migration risk. Avoid the shallow conclusion `PQ primitive => secure system`.

### 5. AI-assisted protocol security is already competitive
The Ethereum Foundation Protocol Security team has publicly described coordinated AI agents finding real protocol-code bugs, including a remotely triggerable libp2p gossipsub panic disclosed as CVE-2026-34219.

**Implication:** Sentinel needs deeper causal reasoning than narrow bug-finding: protocol-spec compliance, distributed-system assumptions, crypto, identity/delegation, infrastructure provenance and incident reconstruction.

## 2026-09-16 → 2026-09-17 fresh intake

### Execution-finality split into concrete security objects
Four new individual IETF Internet-Drafts published 2026-09-16 sharpen the authorization-to-effect problem. `draft-das-execution-handle-01` proposes a Candidate Act Descriptor, scoped non-bearer Execution Handle bound to an exact act/finality sink, atomic consumption, and a Finality Receipt. Companion drafts cover state/policy continuity, third-party decision binding, and finality-bound revocation. These are Informational Internet-Drafts, NOT RFCs or adopted standards.

**Training opportunity:** add `FINALITY_BOUND_AUTHORITY` cases where Sentinel must detect stale-but-cryptographically-valid authorization, replayable effect handles, policy/state changes between decision and commit, and third-party ALLOW evidence that is not actually bound to the protected effect.

**Threat:** agent systems can be fully authenticated yet execute an obsolete or context-swapped authorization after policy, ownership, risk, revocation, or account state changes.

**Competitor gap:** most identity/policy products answer “was this credential/decision valid?”; Sentinel should reason “was it still authoritative for this exact effect at commit time?”

### Agent Trust Profile tries to compose existing identity standards
`draft-mnki-agent-trust-profile-00`, published 2026-09-16, profiles JWS, OAuth/OIDC, SPIFFE/WIMSE, proof-of-possession, AuthZEN and federation concepts for agent identity, principal binding, attenuated delegation, authorization attestations, provenance and revocation. It is an Informational Internet-Draft, not a standard.

**Training opportunity:** cross-standard semantic reasoning: distinguish identity proof, principal binding, delegated authority, constraints, request possession, authorization decision, provenance and revocation.

### PQ migration is becoming runtime/default behavior
Java 27 GA (2026-09-15; fresh ecosystem reporting continued Sep 16-17) includes JEP 527 hybrid post-quantum key exchange for TLS 1.3. Bitcoin PQ discussion on Sep 16-17 also emphasizes that migration/state management and legacy funds can be harder than selecting a primitive.

**Training opportunity:** treat PQ as a lifecycle/operational problem: algorithm negotiation, hybrid fallback, stateful-signature misuse, wallet/key migration, compatibility and rollback—not merely primitive recognition.

## Training / benchmark additions
- `TRUST_CHAIN`: identify the broken trust assumption across multiple layers.
- `DELEGATION_CHAIN`: verify monotonic scope/expiry attenuation over multi-hop delegation.
- `ACTION_FINALITY`: separate proposed, authorized, executed and externally effective actions.
- `FINALITY_BOUND_AUTHORITY`: verify state/policy/revocation continuity at the exact effect boundary.
- `THIRD_PARTY_DECISION_BINDING`: verify that external ALLOW/attestation evidence is bound to the exact act/context.
- `CROSS_CHAIN_CAUSALITY`: reconstruct bridge failures without assuming signature validity proves state validity.
- `PQ_MIGRATION`: map cryptographic dependencies and migration ordering.
- `STANDARD_STATUS`: distinguish RFC/Recommendation from Internet-Draft, EIP/ERC proposal, research and vendor branding.
