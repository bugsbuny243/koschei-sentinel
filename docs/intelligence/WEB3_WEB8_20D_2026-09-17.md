# Web3–Web8 20-Day Intelligence — Koschei Sentinel

Window: 2026-08-29 → 2026-09-19

Sentinel is treated here as a cybersecurity foundation model, not a scanner.

## Existing capability directions
- Trust-chain reasoning across identity, credential, code, observation source, protocol rule, authorization, state transition, effect and evidence.
- Multi-hop agent authorization: authentication != standing capability != delegated scope != per-action authority != execution != effect.
- Execution/action finality and commit-time state/policy/revocation continuity.
- PQ migration as cryptographic dependency, lifecycle, compatibility and operational reasoning.
- Cross-chain causality and standards-status classification.
- Agent registry reliance and software artifact identity continuity.

## 2026-09-19 fresh intake

### RFC 10032 publishes the AEGIS AEAD family — real RFC, but Informational/IRTF
RFC 10032 was announced 2026-09-19. It documents AEGIS-128L, AEGIS-256, AEGIS-128X and AEGIS-256X authenticated-encryption algorithms, plus stream-cipher/MAC modes. It is a CFRG/IRTF product with **Informational** status and explicitly does not specify an Internet Standard.

**Training opportunity:** add `CRYPTO_STATUS_AND_DEPLOYMENT_REASONING` cases: distinguish cryptographic algorithm publication, research-group consensus, protocol negotiation, implementation support, deployment policy and actual security guarantees.

**Threat:** an RFC number can be incorrectly treated as proof that an algorithm is mandatory, negotiated, deployed or suitable for every protocol/context.

**Competitor gap:** Sentinel should reason over both cryptographic construction and standards/deployment provenance rather than merely matching algorithm names.

### AIN-WRP proposes pre-interaction verification for persistent agent identities
`draft-tanase-ain-authoritative-resolution-00`, published 2026-09-18, proposes authoritative resolution of persistent Agent Identity Numbers and relationship-specific state before protected interaction. It explicitly separates persistent identity from credentials, proof-of-control, delegated authority, operational eligibility, policy decision and execution. It is an Individual Submission Internet-Draft with intended Standards Track status — not an RFC or adopted standard.

**Training opportunity:** add `PRE_INTERACTION_AGENT_VERIFICATION`: reason whether identity/operator/endpoint/mandate/restriction/provenance evidence is authoritative, fresh and sufficient before an interaction, without collapsing identity resolution into authorization.

**Threat:** stale or wrong-source relationship data can create a false sense of authority even when a stable identifier resolves correctly.

**Competitor gap:** combine registry/identity evidence with finality-bound authority and runtime-effect reasoning in one causal security model.

### Several March agent-provenance drafts reach expiry without becoming standards
On 2026-09-19, ADL, SPICE Intent Chain, SPICE Inference Chain, RVP and UPIP revisions reach their six-month Internet-Draft expiry dates unless replaced/updated. Their ideas remain useful research signals, but expiry is evidence against treating the named drafts as settled standards.

**Training opportunity:** strengthen `STANDARD_STATUS` with temporal lifecycle: active draft -> updated/replaced/expired -> RFC/abandoned. Agent content/computation provenance concepts should be learned independently of one draft identifier.

## Standards reality
No accepted IETF/W3C generation standard named Web4, Web5, Web6, Web7 or Web8 was identified in this intake. RFC 10032 is a real RFC but Informational/IRTF, not an Internet Standard. AIN-WRP is an Internet-Draft. Expiring agent drafts must not be presented as standards.
