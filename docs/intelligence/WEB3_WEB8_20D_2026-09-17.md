# Web3–Web8 20-Day Intelligence — Koschei Sentinel

Window: 2026-08-29 → 2026-09-18

Sentinel is treated here as a cybersecurity foundation model, not a scanner.

## Existing capability directions
- Trust-chain reasoning across identity, credential, code, observation source, protocol rule, authorization, state transition, effect and evidence.
- Multi-hop agent authorization: authentication != standing capability != delegated scope != per-action authority != execution != effect.
- Execution/action finality and commit-time state/policy/revocation continuity.
- PQ migration as cryptographic dependency, lifecycle, compatibility and operational reasoning.
- Cross-chain causality and standards-status classification.

## 2026-09-18 fresh intake

### Agent Registry Protocol (ARPA) adds a new registry/reliance-decision layer
`draft-sankarshan-agent-registry-protocol-00` was published 2026-09-17 as an Individual Submission with intended Standards Track status. It proposes HTTP/JSON publication and resolution of software-agent operator identity, deployment, typed relationships, bounded delegated authority, lifecycle state and evidence. It is an Internet-Draft, NOT an RFC or adopted standard.

**Training opportunity:** add `AGENT_REGISTRY_RELIANCE` cases. Sentinel should reason about the difference between discovery, claimed operator identity, bounded authority, lifecycle/revocation state, evidence freshness and an actual authorization decision.

**Threat:** a registry record can be syntactically/cryptographically valid while stale, over-broad, superseded or insufficient for the exact requested effect. Registry discovery must not collapse into authorization.

**Competitor gap:** emerging agent stacks are building discovery/identity registries; Sentinel can differentiate by reasoning over whether registry evidence is sufficient and current for the downstream security consequence.

### Plugin4Shell disclosure exposes an agent add-on supply-chain trust failure
AIR Security published Plugin4Shell on 2026-09-17, with broader reporting on Sep 18. The defensive lesson is that pinning/review metadata is not enough if the client does not verify that the materialized plugin code actually corresponds to the reviewed artifact. AIR reports affected coding-agent ecosystems and says fixes shipped for some clients. Treat vendor impact/status as disclosure claims unless independently confirmed by each vendor.

**Training opportunity:** add `ARTIFACT_IDENTITY_CONTINUITY`: distinguish requested artifact identity, resolved artifact, materialized code, reviewed digest, runtime-loaded code and inherited permissions.

**Threat:** agent plugins/skills can inherit broad host/tool permissions; a supply-chain identity mismatch can therefore cross directly into sensitive execution context.

**Competitor gap:** many agent-security products focus on prompt/context attacks. Sentinel should also reason about software provenance and artifact identity from marketplace metadata through runtime effect.

**Safe product direction:** build benchmark/data cases around provenance validation, permission inheritance, update trust boundaries and post-install evidence without reproducing offensive exploitation steps.

## Standards reality
No accepted IETF/W3C generation standard named Web4, Web5, Web6, Web7 or Web8 was identified in this intake. ARPA is an IETF Internet-Draft and individual submission; its intended Standards Track status does not make it an Internet Standard.
