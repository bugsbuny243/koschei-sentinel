# Koschei Sentinel — Monthly Cyber / Agentic-Web Intelligence

**Window:** 2026-09-06 → 2026-10-05  
**Compiled:** 2026-10-06

## Positioning

Koschei Sentinel is treated here as a **cybersecurity foundation model / reasoning system**, not as a scanner. Scanners, SIEMs, sandboxes, debuggers, chain analyzers, MCP gateways and packet tools are evidence-producing tools Sentinel may reason over.

## Core finding of the month

The security boundary is no longer one program or one credential. Consequential agent actions increasingly cross:

`Human/Org → Agent Identity → Credential/Delegation → Tool/MCP/A2A/WebMCP → Intent → Candidate Action → Runtime/Sandbox → External Data/Protocol → State → Effect → Receipt/Proof/Audit`

A valid artifact at one hop does not prove the safety of the final effect.

## Benchmark / reasoning families accumulated this month

### Authority and identity
- **FINALITY_BOUND_AUTHORITY** — authority can expire/revoke between decision and commit/finality.
- **THIRD_PARTY_DECISION_BINDING** — external authorization decisions must bind to the exact action/state.
- **PRE_INTERACTION_AGENT_VERIFICATION** — persistent identity is not proof-of-control, delegation or eligibility.
- **AGENT_REGISTRY_RELIANCE** — registry/discovery information is not current authorization.
- **MULTIPARTY_AUTHORITY_COMPOSITION** — human/org, agent, authorization party and resource policy can disagree.
- **IDENTITY_HANDLE_AUTHORITY_GAP** — handle resolution → canonical identity → credential → delegation → action authority are separate.
- **CERTIFICATE_AUTHORITY_EFFECT_GAP** — valid X.509/PKI identity does not establish safe current effect.
- **DECLARED_MANDATE_BEHAVIOR_DIVERGENCE** — declared mandate/capability can differ from effective capability through composed tools.
- **AUTHORIZATION_SEMANTIC_INTEROP** — identical OAuth primitives can carry different authority semantics across vendors.

### Causality, effect and evidence
- **MODEL_TO_EFFECT_CAUSALITY** — reconstruct model → agent → tool → API/protocol → real effect.
- **ACCOUNTABILITY_CAUSAL_CHAIN** — signed accountability receipt does not prove valid authority/state/effect.
- **EVIDENCE_SEMANTICS** — determine exactly what a receipt proves: identity, execution, state, policy compliance or outcome.
- **AUDIT_EVIDENCE_SEMANTICS** — tamper-evident audit trails can still contain false/incomplete claims.
- **RECEIPT_GATED_EFFECT_CONTINUITY** — bounded effect → receipt → validation → continuation authority.
- **PROPOSAL_EXECUTION_BOUNDARY** — observing/proposing/dry-running is not authority to execute.
- **TURN_EFFECT_CONTINUITY** — cancellation/turn state can diverge from already-triggered tool/external effects.
- **ROLLBACK_EXTERNAL_EFFECT_DIVERGENCE** — source rollback cannot undo already-settled external effects.
- **INTENT_SETTLEMENT_INVARIANT_CONTINUITY** — valid intent/solver logic does not prove adapter/accounting/settlement invariants.
- **COMPONENT_PROTOCOL_ATTRIBUTION** — distinguish module/integration compromise from core-protocol compromise while preserving blast radius.

### Runtime and containment
- **RUNTIME_AUTHORITY_REVOCATION** — handle in-flight actions when authority is revoked.
- **RUNTIME_CONTAINMENT_CONTINUITY** — declared sandbox/network policy must match observed enforcement.
- **CROSS_LAYER_CONTAINMENT_CONTINUITY** — software policy, credential protection, network boundary and hardware observation must agree.
- **SELECTIVE_EXECUTION_CONTAINMENT** — find minimum safe containment surface instead of shutting down an entire runtime.
- **PRECONDITION_ORDERING** — authentication/policy checks only protect effects if they occur before the effect boundary.

### Provenance and supply chain
- **ARTIFACT_IDENTITY_CONTINUITY** — requested → resolved → materialized → verified → runtime-loaded artifact.
- **TRUST_POSTURE_DRIFT** — security posture is time-varying; snapshot freshness matters.
- **SPEC_LIFECYCLE_VALIDITY** — published I-D != adopted draft != RFC != deployed implementation.
- **AGENT_CONTENT_PROVENANCE_CONTINUITY** — resource/fragment/originator/rights/provenance must survive agent transformation.
- **AUTHENTICITY_TRUTH_SEPARATION** — cryptographic authenticity does not establish truth.

### Distributed systems / Web3
- **TRUST_CHAIN_REASONING** — identity, credential, capability, code, tool, external data, protocol, state, effect and evidence form one chain.
- **TRANSITIVE_CAPABILITY_REASONING** — an authorized component may reach unexpected effects through composition/delegatecall/hooks/tools.
- **CROSS_CHAIN_TRUST_COMPOSITION** — reason over verifier/finality/executor combinations, not bridge name alone.
- **ACTIVATION_STATE_REASONING** — implementation support/testnet activation/mainnet activation are different states.
- **DISCOVERY_CAPABILITY_REALITY_GAP** — “supports X” does not mean the requested capability is active now.
- **CUSTODY_OPERATIONAL_RISK_SEPARATION** — key custody, validator/service infrastructure and continuity are distinct risks.

### Post-quantum / cryptographic reasoning
- **PQ_COMPONENT_GRAPH** — PQ account signatures do not imply PQ consensus, transport, admin keys, bridges or data availability.
- **PQ_END_TO_END_GAP** — locate classical dependencies in a claimed PQ system.
- **PQ_CLAIM_EVIDENCE_GRADIENT** — claimed → observed → code-verified → independently reproduced.
- **ENTROPY_PROVENANCE** — entropy source → validation → extraction → runtime health → key material → cryptographic effect.
- **CRYPTO_DESIGN_IMPLEMENTATION_EQUIVALENCE** — secure mathematical design does not prove correct implementation.
- **PRIVACY_BOUNDARY_REASONING** — payment unlinkability, network anonymity, content privacy and behavioral unlinkability are distinct.

## Standards-status rule

Sentinel training/evaluation must distinguish:

`RFC / W3C Recommendation → WG-adopted draft → individual Internet-Draft → W3C Community Group/incubation → research proposal → vendor implementation → production deployment → marketing/WebN label`

An `ietf.org` URL alone does not make a document an IETF standard.

## Web4–Web8 conclusion

No universal W3C/IETF Web4, Web5, Web6, Web7 or Web8 generation standard was found in this month. The technically real transition is toward an **agentic/action Web** built from identity, delegation, authorization, tool protocols, provenance, receipts, machine payments, privacy and effect verification.

## Sentinel architecture direction

Sentinel should learn to answer, with evidence:

1. Why does the agent want this action?
2. Where does authority come from?
3. Is the delegation chain valid and still fresh?
4. Is the action within policy and current state?
5. Does the runtime actually enforce the declared boundary?
6. Does the tool-call effect match the real-world/on-chain effect?
7. Is the state transition safe and economically invariant-preserving?
8. Can the result be independently proven and reconstructed?
9. Which trust assumption broke?
10. Can a transitive capability reach an unexpected resource/effect?
11. Is the runtime-loaded artifact the reviewed artifact?
12. Does the cryptographic/PQ claim cover the entire trust path?
